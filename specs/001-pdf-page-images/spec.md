# Feature Specification: Конвертация PDF в изображения страниц

**Feature Branch**: `001-pdf-page-images`  
**Created**: 2026-04-01  
**Status**: Draft  
**Input**: User description: "Нужно создать простой скрипт, который будет принимать в себя pdf и разбивать его на страницы в формате картинок. Нужно, чтобы картинки хорошо читались, т.к. один из сценариев - это извлечение изображений чертежей, где есть мелкие надписи, тонкие линии, штриховки. Важно хорошее качество."

## Clarifications

### Session 2026-04-01

- Q: Какой формат выходных изображений должен быть основным? → A: PNG по умолчанию, с возможностью выбрать JPEG.
- Q: Какой минимальный уровень качества нужно гарантировать для читаемости чертежей? → A: Эквивалент 300 DPI минимум.
- Q: Как обрабатывать PDF, защищенный паролем? → A: Завершать с понятной ошибкой «требуется пароль».
- Q: Где должен работать сервис и как выдавать результат? → A: Сервис может работать на сервере и должен возвращать результат обработки в ответ на запрос, а не сохранять файлы в директории запуска.
- Q: В каком виде возвращать результат обработки в ответе? → A: Возвращать массив изображений в JSON.

### User Story 1 - Разделение PDF по страницам (Priority: P1)

Пользователь отправляет один PDF-файл на серверную обработку и получает результат с изображениями страниц в предсказуемом порядке в ответе на запрос.

**Why this priority**: Это базовая ценность фичи; без корректного разбиения по страницам сценарий использования невозможен.

**Independent Test**: Можно протестировать на PDF из 3-5 страниц и проверить, что создано ровно столько же файлов изображений с корректной последовательностью страниц.

**Acceptance Scenarios**:

1. **Given** PDF с 4 страницами, **When** пользователь отправляет запрос на обработку, **Then** сервис возвращает 4 изображения страниц в составе ответа.
2. **Given** PDF с обычным текстовым содержимым, **When** завершается обработка, **Then** все изображения открываются без ошибок и соответствуют исходным страницам.

---

### User Story 2 - Высокая читаемость чертежей (Priority: P2)

Пользователь обрабатывает PDF с чертежами и ожидает, что на итоговых изображениях остаются различимыми мелкие надписи, тонкие линии и штриховка.

**Why this priority**: Один из ключевых бизнес-сценариев напрямую зависит от качества итоговых изображений.

**Independent Test**: Можно протестировать на контрольном PDF с инженерным чертежом и визуально подтвердить читаемость мелких подписей и тонких элементов.

**Acceptance Scenarios**:

1. **Given** PDF с чертежом и мелкими деталями, **When** скрипт завершает конвертацию, **Then** на изображениях различимы мелкие подписи и тонкие линии при увеличении до рабочего масштаба.
2. **Given** PDF со штриховкой и плотной графикой, **When** пользователь открывает результат, **Then** штриховка не сливается в сплошные пятна и остается читаемой.

---

### User Story 3 - Понятные ошибки и повторный запуск (Priority: P3)

Пользователь получает понятное сообщение, если передан некорректный файл или обработка не может быть выполнена, и может исправить входные данные и повторить запуск.

**Why this priority**: Повышает надежность использования и снижает время на диагностику проблем.

**Independent Test**: Можно передать поврежденный или неподдерживаемый файл и проверить, что пользователь получает четкую причину ошибки без частично некорректного результата.

**Acceptance Scenarios**:

1. **Given** поврежденный PDF-файл, **When** пользователь запускает скрипт, **Then** скрипт завершает работу с понятным сообщением об ошибке и без ложного успеха.
2. **Given** путь к несуществующему файлу, **When** выполняется запуск, **Then** пользователь получает сообщение о том, что входной файл не найден.

---

### Edge Cases

- PDF содержит одну страницу очень большого размера (например, формат чертежа), и итоговый файл изображения получается значительно больше стандартного.
- PDF содержит страницы с разной ориентацией (портрет/альбом), и порядок с ориентацией должен сохраниться.
- В PDF присутствуют пустые или почти пустые страницы.
- Входной PDF защищен паролем или имеет ограничения на чтение.
- В запросе передан пустой или некорректный `pdf_base64`.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система должна принимать PDF в запросе на обработку и запускать конвертацию всех его страниц в изображения.
- **FR-002**: Система должна возвращать каждую страницу как отдельное изображение в ответе на запрос.
- **FR-002a**: Система должна использовать PNG как формат выходных изображений по умолчанию и позволять пользователю выбрать JPEG как альтернативу.
- **FR-003**: Система должна сохранять порядок страниц в массиве ответа так, чтобы пользователь мог однозначно сопоставить элемент массива с исходной страницей PDF.
- **FR-004**: Система должна обеспечивать высокий уровень визуальной читаемости выходных изображений для документов с мелким текстом, тонкими линиями и штриховкой.
- **FR-004a**: Для сценария с чертежами система должна обеспечивать качество конвертации не ниже эквивалента 300 DPI.
- **FR-005**: Система не должна требовать указания выходной директории в клиентском окружении.
- **FR-006**: Система должна сообщать пользователю о результате обработки: успешное завершение с количеством созданных файлов или понятная причина ошибки.
- **FR-007**: При пустом или некорректном входном PDF, а также при невозможности прочитать документ, система должна завершаться с ошибкой без частично успешного результата.
- **FR-007a**: Если входной PDF защищен паролем, система должна завершаться с понятной ошибкой о необходимости пароля.
- **FR-008**: Система должна поддерживать многостраничные PDF как основной сценарий использования.
- **FR-009**: Система должна работать в рамках одного запуска без ручного вмешательства пользователя между страницами.
- **FR-010**: Система должна формировать результат обработки как возвращаемый ответ и не требовать записи изображений в директорию запуска.
- **FR-011**: Система должна возвращать результат обработки как JSON-объект с массивом изображений страниц.

### Key Entities *(include if feature involves data)*

- **Input PDF**: Исходный документ, который содержит одну или несколько страниц для преобразования.
- **Page Image**: Выходной артефакт для одной страницы PDF с атрибутами: номер страницы, формат изображения (PNG по умолчанию, опционально JPEG), содержимое изображения в JSON-ответе.
- **Conversion Result**: Результат выполнения запуска, включающий статус (успех/ошибка), количество обработанных страниц и текст сообщения для пользователя.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: В 100% успешных запросов с валидным многостраничным PDF количество возвращенных изображений равно количеству страниц в исходном документе.
- **SC-002**: Не менее 95% тестовых документов с инженерными чертежами проходят визуальную проверку читаемости мелких подписей и тонких линий без повторной конвертации.
- **SC-005**: В 100% запусков, где выбран режим качества по умолчанию, изображения чертежей формируются с качеством не ниже эквивалента 300 DPI.
- **SC-003**: Пользователь получает итоговый результат (успех или понятная ошибка) в ответе на один запрос без необходимости ручной постобработки в не менее чем 90% типовых случаев.
- **SC-004**: Не менее 90% пользователей, впервые использующих скрипт, успешно выполняют конвертацию тестового PDF без дополнительной инструкции.

## Assumptions

- Обработка может выполняться на сервере по запросу клиента.
- Первый релиз ориентирован на обработку одного PDF за один запуск; пакетная обработка нескольких PDF вне области текущей фичи.
- Результат нужен в виде изображений страниц, возвращаемых в ответе; дополнительное извлечение данных из изображений в этой фиче не рассматривается.
- Проверка качества читаемости выполняется на согласованном наборе контрольных документов, включая чертежи с мелкими деталями.
